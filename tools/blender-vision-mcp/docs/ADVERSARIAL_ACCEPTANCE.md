# Adversarial security acceptance

VisionMCP has a fixed, source-bound adversarial benchmark for the security
conditions required by the 100-plus closure lane. A passing receipt means that
every declared attack was rejected or safely neutralized by an executed guard.
It is not a declaration that a helper exists, and an omitted case cannot pass.

Run it from a clean source revision:

```bash
uv run bvmcp benchmark bootstrap-adversarial \
  --output artifacts/adversarial
```

The output directory must be new or empty. The receipt binds the full Git source
SHA, fixed manifest SHA-256, every preserved input SHA-256, every result, the
SQLite/runtime identity, and four negative controls. Attack inputs and results
are retained under `attacks/`; hostile GLB and BLEND bytes are retained beside
their input declaration. The benchmark makes no external network request.

## Fixed attack surface

| Attack class | Executed boundary | Required result |
| --- | --- | --- |
| malicious web prompt injection | captured text remains `UNTRUSTED_OBSERVED_CONTENT`; instruction promotion rejects recognized injection | rejected |
| poisoned Figma/Storybook exports | strict bounded JSON, prototype-key rejection, confined import paths, non-finite/depth/node/string limits, production adapter integration | rejected |
| hostile GLB/BLEND | bounded non-symlink GLB structural validation plus BLEND header preflight; no untrusted auto-script execution | rejected |
| path traversal | resolved path must remain below the governed root | rejected |
| symlink escape | resolution cannot leave the governed root; artifact/design/3D inputs also reject linked inputs | rejected |
| stale source maps | source revision and current source/generated byte digests must all match | rejected |
| artifact substitution | the content-addressed store rehashes bytes and reconciles registered size/path before materialization | rejected |
| benchmark leakage | builder and oracle roots are disjoint, link-free, bounded, and scanned for sealed canaries | rejected |
| evaluator tampering | canonical evaluator payload must match its fixed SHA-256 | rejected |
| secret exposure | secret-bearing keys and credential-shaped values cannot enter governed configuration/evidence | rejected |
| unauthorized asset reuse | exact artifact registration and an explicit usable rights state are both mandatory | rejected |
| unsafe generated backend code | executable keys/callables are rejected by the actual generative proposal store before persistence | rejected |
| auth bypass | non-public endpoints require authentication; permission endpoints require every declared permission | rejected |
| SQL injection | a hostile value is bound as a SQLite parameter; it matches no row and cannot alter the table | neutralized |
| cross-tenant leakage | actor tenant must equal the expected tenant whenever a tenant boundary is declared | rejected |
| performance score gaming | source revision, raw metric digests, fixed thresholds, and every preservation gate are mandatory | rejected |
| local visual repair breaking another route/state | a local pass cannot be accepted unless every declared route/state regression gate passes | rejected |

The design adapters intentionally record prompt-injection findings rather than
discarding observed labels or copy. Such content may remain evidence, but
`instruction_authority` is always false. Structural poison is rejected before
graph compilation.

The application compiler already refuses tenant-scoped deployment because the
bounded compiler has no authorized tenant adapter. The tenant policy in this
suite specifies the enforcement required before that deployment boundary can be
expanded; it does not convert the current refusal into a production
multi-tenant claim.

## Anti-gaming authority

`SecurityAcceptanceAuthority` requires the exact ordered set of 17 attack IDs,
one passing digest-bound result for each input, and the exact four negative
controls:

1. remove one attack result;
2. substitute one preserved input digest;
3. remove an attack from the manifest-required set;
4. relabel one result as failed.

Each mutation must itself be rejected. `PASS` is issued only after those
controls pass and all 17 real attack cases have the required disposition.

## Claim boundary

This benchmark proves deterministic handling of its fixed attack corpus on the
bound source tree. It does not prove the absence of unknown vulnerabilities,
replace dependency review or independent penetration testing, or authorize
execution of untrusted BLEND automation. GLB/BLEND handling here is a bounded
preflight boundary. Deeper content safety must still use isolated Blender with
factory startup, auto-execution disabled, an allowlisted operation, and network
access disabled.
